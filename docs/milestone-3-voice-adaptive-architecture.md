# Milestone 3: adaptive voice call mode

SCAMSTAGE provides browser-based voice turn-taking for a fictional
fraud-awareness exercise. It is not telephony: there are no phone numbers,
PSTN connections, WebRTC streams, or real financial systems. Every
organization, caller name, alert, account, response, and transaction in the
exercise is fictional.

## Runtime flow

```text
Start voice call
  -> create an active voice session
  -> Ollama writes the fictional opening from authority + vague alert strategy
  -> validator accepts the bounded caller wording
  -> ElevenLabs returns synthetic audio, or text-only voice fallback is shown
  -> browser listens for one participant turn
  -> fast_safety_policy classifies the final transcript
  -> rolling deterministic engine selects strategy, tactics, risk, and evidence
  -> Ollama writes the next bounded caller line
  -> ElevenLabs voices it and the browser listens again
  -> repeat until the participant clicks End call safely
  -> deterministic score/debrief is returned immediately
  -> optional Nemotron evaluation runs in the background
```

The opening is also generated by Ollama when `DIALOGUE_PROVIDER=ollama`; there
is no premade active-call opening in that mode. Only the final recognized
transcript is sent to the backend. SCAMSTAGE does not store raw microphone
audio. Browser speech recognition may use a browser vendor's speech service, so
participants must use synthetic practice speech and must never provide real
personal information, passwords, account details, payment details, or codes.

## Deterministic active-call policy

The local fast safety policy remains authoritative. After every participant
response it records:

- participant intent, confidence, and evidence;
- risk score and risk band;
- tactic labels;
- the next rolling pressure strategy;
- a timeline event with before/after stage and risk.

The rolling strategy can move among authority, explanation, urgency,
clarification, verification resistance, fictional sensitive-request pressure,
alternative pressure, repetition, release, and re-anchoring. It is not a
terminal path. A question can remain in clarification; a verification request
can trigger verification resistance; discomfort or refusal can receive a
fictional persistence/release response; and “I am hanging up” is still an
active turn.

Active participant turns never set `completed=true`, regardless of the risk
score, apparent compliance, refusal, skepticism, clarification, or turn count.
The only normal terminal action is `POST /api/sessions/{session_id}/end`, which
sets `call_active=false`, records `user_ended_call`, and creates the debrief.

## Ollama boundary

Ollama receives only bounded context: the scenario and fictional organization,
fictional caller name, deterministic strategy, permitted tactics, latest
participant response, at most the last eight flat transcript messages, and a
hidden risk band. The system prompt requires one or two natural spoken
sentences, 12–42 words, strict JSON, no model/tool/prompt references, no real
information requests, and no out-of-character safety boilerplate in ordinary
caller dialogue.

Ollama writes wording only. It cannot choose intent, risk, tactics, strategy,
state, scoring, terminal status, or debrief outcome. Output is validated for
shape, length, unsafe requests, prompt-injection text, real-world contact
patterns, and repeated caller lines.

When Ollama is unavailable, times out, or returns invalid/unsafe output, the
orchestrator preserves the active session and pending participant turn without
advancing risk, strategy, history, or timeline. The response reports a truthful
`ollama_unavailable`, `ollama_timeout`, or `ollama_invalid_output` status and
offers an explicit retry action. While Ollama is the configured provider, the
active call never silently substitutes authored dialogue.

## Browser controller

`apps/web/src/voice.js` owns one call-session state machine. Its states include
`idle`, `starting`, `requesting_microphone`, `caller_speaking`, `listening`,
`transcribing`, `submitting`, `processing`, `paused`,
`dialogue_unavailable`, `terminal`, `error`, and `text_fallback`.

The controller uses `window.SpeechRecognition` or
`window.webkitSpeechRecognition` with one non-continuous recognition turn at a
time, interim captions, and the browser language. Generation tokens and
submission guards prevent old audio or recognition callbacks from changing a
restarted session. If speech recognition is unavailable or permission is
refused, caller audio and the typed turn form remain available in the same
session. If autoplay is blocked, caller text and the audio control remain
visible, with a button to continue to listening.

The controller never infers terminal state from a stage, intent, risk score, or
caller wording. It stops listening and playback only when the explicit end
control succeeds or the user restarts/changes the scenario.

## API and debrief

`POST /api/sessions` creates the session and returns the live opening status.
`POST /api/sessions/{id}/turns` records one active participant turn and returns
the next caller response. `POST /api/sessions/{id}/dialogue/retry` retries the
pending opening or caller response. `POST /api/sessions/{id}/end` ends the
call, persists the end event, and returns the deterministic debrief without
waiting for Nemotron.

The debrief is computed from the complete successful transcript and timeline.
It includes the training risk indicator (explicitly not a personal assessment),
boundaries set, whether independent verification was requested, observed
tactics, evidence, safer response examples/guidance, and the full event
history. A bounded terminal Nemotron evaluator may later add an independent
evaluation card; it cannot alter the deterministic score or outcome.

## Provider status

- `fast_safety_policy` means the local active-turn classifier made the decision.
- `Ollama` means validated live caller wording was accepted.
- `ollama_unavailable`, `ollama_timeout`, or `ollama_invalid_output` means the
  caller line is pending retry; no authored active-call line was substituted.
- `ElevenLabs` means synthetic caller audio was generated.
- `voice_fallback` means caller text remains usable without audio.
- `Independent evaluation: pending` means the debrief already returned while a
  terminal Nemotron review is attempted.
- `Independent evaluation: NVIDIA Nemotron` means a validated independent
  review was accepted; it never replaces the deterministic result.
- `Independent evaluation: deterministic fallback` or `unavailable` means the
  immediate deterministic debrief remains authoritative.

## Demo

From the repository root:

```bash
.venv/bin/python -m services.api
```

Open <http://127.0.0.1:8000>, select **Fictional bank fraud**, and choose
**Start voice call**. Use the following fictional responses:

1. `What exactly is this alert about?`
2. `How do I know you are really from the credit union?`
3. `I am uncomfortable continuing this conversation.`
4. `I will call the number on my card instead.`
5. `I am just going to hang up.`

Verify that all five responses produce active Ollama caller lines and that the
call remains active after the fifth. Then click **End call safely** and verify
the immediate debrief, timeline, risk, evidence, provider labels, and optional
terminal-only Nemotron status.

## Known limitations

- Native speech recognition support varies by browser and may require a secure
  origin and microphone permission. Unsupported browsers use typed fallback.
- Browser autoplay policy may require pressing **Play caller response** before
  the next listening turn can begin.
- This is half-duplex browser turn-taking, not a full-duplex or real phone
  call; the microphone is closed while caller audio plays.
- Ollama and ElevenLabs availability depends on the local/provider
  configuration. Their statuses are surfaced without changing deterministic
  risk/state decisions.
- Hosted Nemotron is best-effort and terminal-only. It can time out or return
  invalid output; the deterministic debrief remains the source of truth.
- Sessions are in memory and generated audio is local runtime data. This is a
  synthetic localhost demo, not a production retention or account system.
